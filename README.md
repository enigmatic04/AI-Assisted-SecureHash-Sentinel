# AI-Assisted Secure File Integrity Monitoring System

A Python-based cybersecurity application that monitors file integrity using SHA-256 cryptographic hashing. The system registers the original hash of a file and detects subsequent modifications by comparing the stored hash with the current hash.

The application provides a simple web interface using Flask, HTML, CSS, and JavaScript, along with SQLite-based verification history and security analysis features.

---

## Overview

File integrity is an important part of cybersecurity because unauthorized modification of files can indicate accidental changes, tampering, or other security events.

This project uses the SHA-256 hashing algorithm to generate a unique cryptographic hash for uploaded files. The generated hash is compared with the previously registered hash of the file.

If both hashes match, the file is considered unchanged.

If the hashes are different, the system reports that the file has been modified.

In addition to basic integrity verification, the system performs hash-difference analysis, avalanche-effect analysis, risk classification, and SHA-256 performance measurement.

An AI-assisted analysis module can additionally provide a concise explanation of detected security events and recommended actions.

---

## Features

### 1. SHA-256 File Hashing

- Generates SHA-256 hashes for uploaded files.
- Uses Python's built-in `hashlib` library.
- Reads files in chunks for efficient processing.

### 2. File Integrity Verification

- Registers the original SHA-256 hash of a file.
- Compares subsequent uploads against the registered hash.
- Detects whether the file has been modified.

Possible results include:

- New File
- Integrity Verified
- File Modified

### 3. Avalanche Effect Analysis

The system compares two SHA-256 hashes at the bit level.

It calculates:

- Number of different bits
- Percentage of different bits

This demonstrates the avalanche effect of cryptographic hashing, where a small change in input can result in a significantly different hash.

### 4. Risk Analysis

The hash-difference percentage is used as an experimental risk indicator.

The current classification is:

| Hash Difference | Risk Level |
|----------------|------------|
| 0% - 20%       | LOW        |
| >20% - 50%     | MEDIUM     |
| >50%           | HIGH       |

The risk classification is intended for educational analysis of hash changes. It does not determine whether a file is malicious.

### 5. Performance Benchmarking

The system measures the execution time required to calculate the SHA-256 hash of the uploaded file.

The result is displayed in seconds.

### 6. Verification History

SQLite is used to maintain:

- Registered files
- Original SHA-256 hashes
- Current hashes
- Verification status
- Risk level
- Hash-difference percentage
- SHA-256 execution time
- Verification timestamp

### 7. Web Interface

The application provides a simple web-based interface for:

- Uploading files
- Checking file integrity
- Viewing hash information
- Viewing security analysis
- Viewing verification history

### 8. AI-Assisted Security Analysis

The AI module can analyze the security metadata generated by the system and provide:

- Explanation of what happened
- Possible reasons for the change
- Recommended security action

The AI does not determine file integrity. The actual integrity decision is performed by SHA-256 hash comparison in Python.
